1 Objectives
This experiment uses Python and OpenCV to perform camera calibration for a mobile-camera image set captured
with a planar checkerboard. Its objectives are:
  1. to understand the relationships among the world, camera, image, and pixel coordinate systems and the
     pinhole camera model;
  2. to distinguish intrinsic parameters from extrinsic parameters and understand the roles of focal length,
     principal point, and lens distortion coeﬀicients;
  3. to use checkerboard corner detection, subpixel refinement, and cv2.calibrateCamera;
  4. to obtain the camera matrix, distortion coeﬀicients, and per-view poses, and to evaluate the fit using
     reprojection error;
  5. to assess how checkerboard coverage, camera pose, and corner quality affect the calibration result.
    All numerical results in this report come from the recorded JPEG data and the oﬀicial NPZ result file. No
hardware or calibration value is inferred from a default configuration.


2 Principles
2.1 Coordinate Systems and the Pinhole Model
The world coordinate system describes points on the calibration board. The camera coordinate system is
centered at the optical center. The image coordinate system represents continuous image-plane coordinates,
whereas the pixel coordinate system uses discrete image coordinates referenced to the upper-left image corner.
Let Xw = (Xw , Yw , Zw )T be a point in world coordinates and Xc = (Xc , Yc , Zc )T the same point in camera
coordinates. The extrinsic parameters are a rotation matrix R and a translation vector t:

Real lenses make the observed image deviate from ideal pinhole projection. Let r2 = x2 + y 2 . A common radial
distortion model is                                                         

                                                                                                               (5)

length, the report must preserve the returned order and length.


2.3 Planar Calibration and the Zhang Method
Set the checkerboard plane to Zw = 0 and define board coordinates using the square size. The mapping from a
point on the plane to its image is a homography:
                                             
                                     u         Xw                       
                                  s  v  = H  Yw  , H = K r1 r2 t ,                                  (7)
                                      1          1

where r1 and r2 are the first two columns of the rotation matrix. Multiple views of the same checkerboard
provide homography constraints. The orthogonality and unit-length constraints of the rotation columns jointly
estimate the intrinsic parameters and then the pose of each view. A nonlinear optimization finally refines the
intrinsic parameters, distortion coeﬀicients, and extrinsic parameters by minimizing the discrepancy between
observed and projected corners.
     In the program, the checkerboard object points lie on Zw = 0, and the detected image points form the
corresponding two-dimensional observations. The function cv2.calibrateCamera performs the calibration
from these correspondences. The checkerboard configuration and square size must match the physical board;
otherwise the translation-vector scale is not physically meaningful.

4 Data Acquisition
4.1 Checkerboard and Coordinate Convention
The calibration target is a planar black-and-white checkerboard. The option --checkerboard specifies the
number of checkerboard inner-corner columns and rows, while --square-size specifies the physical side length
of one square. The present run used 8 × 5 inner corners and a 3 cm square size, with square_size=3.0. The
upper-left inner corner was set to (0, 0, 0); the two board directions define Xw and Yw , and all board points
have Zw = 0. This convention is consistent with the planar model in Equation 7.

The input set contains 18 JPEG files under task2/images_jpg/, each with resolution 5712×4284. JPEG EXIF

overexposure. A separate pose-coverage log remains to be organized from the original acquisition.
    The program reads task2/images_jpg/ and preserves the original filenames, allowing the NPZ image_

5 Experimental Procedure
  1. Prepare the planar checkerboard, measure the physical square size, and record the number of inner corners
     in each direction.
  2. Capture clear images at different distances, translations, and tilt angles. Record the phone model, rear-
     camera use, image resolution, and acquisition settings.
  3. Read each image and check whether it can be loaded. A read failure is recorded for that file and does not
     stop processing of the remaining images.
  4. Convert a color image to grayscale with cv2.cvtColor, then detect checkerboard inner corners with
     cv2.findChessboardCorners. Record the two-dimensional corners for successful images and the filename
     and reason for failures.
  5. Refine detected corners to subpixel accuracy with cv2.cornerSubPix.
  6. Generate planar three-dimensional object points from the checkerboard configuration and square size, and
     pair them with the two-dimensional image points. The geometry follows Equation 7.
  7. Check the number of valid images and the consistency of image sizes. Mixed resolutions and fewer valid
     views than --min-images must be rejected.
  8. Call cv2.calibrateCamera to estimate the camera matrix, distortion coeﬀicients, and the rotation and
     translation vectors for each valid view. The camera matrix is defined in Equation 3; the distortion model
     is given in Equations 4 and 5.
  9. Reproject the three-dimensional points with cv2.projectPoints, compute pointwise errors using Equa-
     tion 8, and summarize the three error definitions in Section 7.
 10. Save the camera matrix, distortion coeﬀicients, poses, error statistics, image counts, and detection status
     to the NPZ result. If requested, use cv2.undistort to save corrected images.
 11. Use the recorded result and the criteria in Section 8 to assess parameter consistency and data quality.
    The complete control flow implemented by the OpenCV program is summarized in Figure 1.

8 Analysis
This analysis is based on the 18 real JPEG images, the oﬀicial result file, and the corresponding OpenCV run.
Conclusions are limited to the current 5712 × 4284 image-coordinate setup, 8 × 5 checkerboard inner corners,
and 3 cm square size. A pixel reprojection error is not treated as a direct guarantee of physical measurement
accuracy.


8.1 Scope of the plotted variation
The camera matrix K and distortion vector d are fitted jointly from all valid views, so this experiment produces
one global estimate of fx , fy , cx , cy and (k1 , k2 , p1 , p2 , k3 ). It would be methodologically incorrect to draw 18
apparent intrinsic-parameter trajectories by copying the same global values or by fitting a single planar view
independently without reporting a separate uncertainty protocol. The additional figures therefore use quantities
that really have one value per image: reprojection RMS, rotation and translation vectors, detected-corner
locations, and the response of the fitted distortion model over normalized radius. This gives more diagnostic
information without fabricating parameter fluctuations.

The global OpenCV RMS is 2.06424401 px, the global mean pointwise distance is 1.65696931 px, and the
arithmetic mean of the 18 per-image RMS values is 1.90750642 px. The per-image distribution in Figure 2 has

3.625463 px, and sample standard deviation 0.811881 px. The largest residuals occur in IMG_5513 (3.625463
px), IMG_5514 (3.115401 px), IMG_5516 (2.684612 px), and IMG_5509 (2.665750 px).
     These values indicate that corner localization quality is not identical across views, even though all images
passed the program’s validity checks. A higher residual can result from blur, glare, partial perspective com-
pression, printing or board flatness, or local corner ambiguity; the residual alone cannot identify which cause
occurred. The per-view errors have an exploratory Pearson correlation of approximately r = 0.38 with board-
normal tilt and r = −0.32 with board-origin distance. With only 18 observations, these weak correlations are
not evidence of a causal trend, but they suggest that strongly tilted views deserve visual inspection. Removing
such a view without rerunning calibration and documenting the effect would also be premature.
     At the current resolution, the OpenCV RMS is approximately 0.03614% of the image width and 0.04818%
of its height. Thus the error is small relative to the full image dimensions, but a high-resolution image makes
a fixed pixel error appear smaller in relative terms. The RMS is an internal fit residual, not an independent
validation measurement, and comparisons across resolutions should account for image scale and acquisition
conditions.


8.4 Pose diversity and calibration geometry
The translation plot in Figure 4 shows meaningful geometric variation. The checkerboard-origin depth tz ranges
from 24.705 to 90.828 cm, while ∥t∥ ranges from 27.559 to 91.815 cm. The lateral components span 24.583
cm in x and 23.001 cm in y. The board was therefore not observed at one fixed distance and one fixed lateral
location.
     The orientation plot in Figure 5 gives a complementary view. The Rodrigues-vector norm ranges from
2.688◦ to 173.651◦ , and the board-normal tilt ranges from 2.683◦ to 62.936◦ , with a median tilt of 29.703◦ .
The Rodrigues vector is an axis-angle representation of the board-to-camera rotation; its component values and
norm are not three independent physical tilt angles. The board-normal tilt is easier to interpret as the angle
between the board plane normal and the camera optical axis. The near-180◦ norm in IMG_5516 may reflect the
rotation representation and the board’s in-plane orientation, so it should be checked against the image rather
than automatically treated as a bad calibration pose.


8.5 Corner coverage and distortion extrapolation
All 18 candidate JPEG files passed image reading, 8 × 5 corner detection, and the resolution check. Every valid
image contributes 40 refined corners, giving 720 observations. Figure 3 shows that the union of those corners
extends from approximately x = 0.191 to 0.814 and y = 0.182 to 0.792 in normalized image coordinates. In
physical pixels, the board observations therefore occupy a central region rather than the full 5712 × 4284 sensor
frame.
     This coverage is suﬀicient for a working calibration run, but it limits the evidence available for the outer-
most distortion behavior. Figure 6 is computed from the global coeﬀicient vector, not from measured corner
displacements at every radius. At the image-corner radius in the current camera model, the radial scale factor
is approximately 0.476, while the tangential displacement is approximately 0.004–0.011 normalized coordinate
units over viewing angle. The radial polynomial’s strong high-radius response may be real, but the present
dataset does not densely observe that region. Additional views placing the checkerboard near the left, right,
top, bottom, and four corner regions would be the most valuable next experiment.

8.7 Limitations and practical conclusion
The experiment demonstrates a reproducible OpenCV calibration for the supplied iPhone 15 Pro rear-camera
images, with translations expressed in centimeters because square_size=3.0 was supplied in centimeters. The
result is tied to the selected rear-camera mode, resolution, crop, focus, and computational photography pipeline.
The NPZ file does not contain a covariance estimate for the global parameters, and the current acquisition does
not document a per-image pose label independent of the estimated extrinsics. Consequently, the recovered K
and d are suitable as calibrated parameters for this image-coordinate setup, but they should be re-estimated if
the phone changes lens mode, resolution, crop, or focus. The most direct improvement is to add more edge and
corner views, keep the board sharp and flat, and compare the new per-view residual distribution with Figure 2.


9 Conclusion
This experiment completed OpenCV camera calibration using 18 real JPEG images from the rear camera of an
iPhone 15 Pro. The calibration used an 8 × 5 checkerboard-inner-corner configuration and a 3 cm square size.
The program produced the camera matrix, five distortion coeﬀicients, 18 rotation vectors, and 18 translation
vectors, and recorded OpenCV RMS, mean pointwise reprojection error, and mean per-image RMS. All 18
candidate images were valid; no image-read, corner-detection, or resolution failures occurred.
     The run used square_size=3.0, so translation vectors are expressed in cm, while the camera matrix and
pixel-coordinate distortion results describe the present image model. JPEG EXIF and the acquisition record
identify the Apple iPhone 15 Pro rear camera. The exact rear-lens focal length was not recorded and is not
inferred here. A detailed pose-coverage log should still be added before submission, but it does not affect the
numerical readback of the oﬀicial NPZ result.
