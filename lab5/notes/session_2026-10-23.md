# Lab5 session notes — 2026-10-23 (Claude Code)

## Environment
- Ubuntu 20.04 (WSL2), ROS Noetic, 12 cores. System OpenCV is 4.2 (Debian dfsg build: no
  nonfree, so no SIFT/SURF).
- Official 2023 ROS1 stencil copied from `lab1/vnav-codes/lab5` (the current
  MIT-SPARK/VNAV-labs GitHub repo is the 2024 ROS2 version with AKAZE/BRISK, not used).
- `opencv3_catkin` (OpenCV 3.4.2 + contrib, xfeatures2d incl. SIFT/SURF) built in
  4 min. Changes to the official CMakeLists: python bindings, VTK/viz and FFMPEG off
  (not needed; viz breaks with VTK7 on 20.04), `make -j${NPROC}` via ProcessorCount.
- `glog_catkin`/`gflags_catkin` replaced by system libglog/libgflags (find_library).
- cv_bridge exports the system OpenCV 4.2 libs in `catkin_LIBRARIES`, so at first
  `track_features` linked highgui/calib3d/video from both 3.4 and 4.2. Headless runs
  worked, but with a display `imshow` aborted ("GTK+ 2.x symbols detected", 3.4 highgui =
  GTK2, 4.2 highgui = GTK3), and symbols could resolve to either version. Fixed with
  `list(FILTER catkin_LIBRARIES EXCLUDE REGEX "libopencv_...so.4")`; now only
  libcv_bridge pulls core/imgproc/imgcodecs 4.2. All results were regenerated after
  this fix (first-pass summary kept only in the session scratchpad).
- TeX: `sudo` drops the proxy env vars, so apt needs
  `-o Acquire::http::Proxy=$http_proxy`.

## Pitfalls found
- Stencil `imageCallback` kept `prev_image = image` where `image` comes from
  `toCvShare` (no ownership) → now `clone()`; first frame is skipped instead of being
  matched against itself (which would give 100 % inliers).
- `rosrun ... _param:=v` leaves private params on the parameter server: the first pair
  sweep silently reused the previous config's params. `run_experiments.py` now deletes
  `/lab5_tracker` before every run (all reported numbers come from the fixed runs).
- FLANN-LSH vs BF on ORB/BRIEF: same matches (LSH(20,10,2) finds the exact NN for
  498/500 ORB descriptors, cross-checked in Python), but the LSH index is rebuilt for
  every frame pair → much slower than brute-force Hamming. BF is used for ORB/FAST.
- ORB with the stencil's `nlevels=1` fails on box→box_in_scene (scale change).
